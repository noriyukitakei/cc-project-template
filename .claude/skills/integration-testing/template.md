# 結合テスト仕様書

各テストケースは「メタブロック（固定フィールド）＋詳細セクション」のブロック形式で記述する。

- メタフィールドは値を固定し、後段の自動抽出（実行手段ごとのグループ化・手動ケースの抽出など）を安定させる。
  - `実行手段` は `pytest` / `playwright` 等のツール名、または `manual` のいずれか（自由文禁止）。`manual` が旧 `自動化: manual` を兼ねる。
  - 結合テストは同一レベル内で `pytest`（API↔DB連携）と `playwright`（画面をまたぐ連携）が混在しうるので、ケースごとに明示する。
  - `実行手段: manual` の場合は `理由` を必須とする（なぜ自動化できないかを1行で）。
- `ID` は見出しとフィールドの両方に持たせ、テストコード・CIレポート・実行管理を貫通するキーとする。
- 合否などの実行結果はここに書かない（仕様書は仕様の正本であり、結果は CI / 実行管理側で持つ）。

## IT-AUTH-001 ログイン後プロフィール取得

- **ID**: IT-AUTH-001
- **観点**: API間連携
- **実行手段**: pytest
- **理由**: -

### 概要

ログイン後にプロフィールAPIへアクセスできることを確認する。

### 前提条件

- auth-service が起動していること
- profile-service が起動していること
- Redis が利用可能であること

### 入力

- email: test@example.com
- password: correct-password

### 手順

1. Login API を呼び出す
2. token を取得する
3. Profile API を呼び出す
4. プロフィール情報を取得する

### 期待結果

- Login API が HTTP 200 を返すこと
- token が正常に発行されること
- Profile API が HTTP 200 を返すこと
- プロフィール情報が取得できること

### 備考

API Gateway 経由で実施する。

## IT-AUTH-002 Redis障害時ログイン確認

- **ID**: IT-AUTH-002
- **観点**: 外部サービス障害
- **実行手段**: manual
- **理由**: Redis停止という外部状態の再現が自動環境で不安定なため（testcontainers導入後に再評価）

### 概要

Redis が利用できない場合に、ログイン処理が適切にエラー処理されることを確認する。

### 前提条件

- auth-service が起動していること
- Redis を停止していること

### 入力

- email: test@example.com
- password: correct-password

### 手順

1. Redis を停止する
2. Login API を呼び出す
3. エラーレスポンスを確認する
4. ログ出力内容を確認する

### 期待結果

- Login API が HTTP 503 を返すこと
- システムが異常終了しないこと
- エラーログに相関IDが出力されること

### 備考

Redis 接続タイムアウト時の挙動も確認対象に含める。

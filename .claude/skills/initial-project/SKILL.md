# プロジェクト初期化スキル

このスキルは、プロジェクト立ち上げに必要なドキュメントを順番に作成するためのスキルです。

## 全体の流れ

プロジェクト初期化は以下の4フェーズで進みます。各フェーズが完了したら**必ずユーザーの承認を得てから次へ進んでください**。承認なしに次フェーズへ進むことは禁止です。

```
フェーズ1: アイデア検討（対話形式）
    ↓ ユーザー承認
フェーズ2: 要件定義書の作成
    ↓ ユーザー承認
フェーズ3: 基本設計書の作成
    ↓ ユーザー承認
フェーズ4: 詳細設計書の作成
    ↓ ユーザー承認（完了）
```

---

## フェーズ1: アイデア検討（対話形式）

要件定義に入る前に、ユーザーとの対話を通じてプロジェクトのアイデアを整理します。このフェーズの目的は「何を作るか」の輪郭を掴むことであり、細かい仕様を決めることではありません。

### 対話で引き出す内容

以下の観点を中心に、ユーザーへの質問と回答のやり取りを通じて情報を集めてください。一度に全部聞かず、会話の流れに合わせて自然に深掘りしてください。

- **背景・動機**: なぜこのプロジェクトを始めるのか。どんな課題や不満を解決したいのか
- **目的**: このプロジェクトで実現したいことは何か
- **ターゲットユーザー**: 誰が使うのか。どんな状況で使うのか
- **主要機能のアイデア**: 最低限あってほしい機能は何か。あると嬉しい機能は何か
- **制約・前提**: 技術的・予算的・期間的な制約はあるか

### アイデアサマリーの保存

対話が一通り終わり、アイデアの全体像が見えてきたら、以下のパスにサマリーを保存してください。

- **保存先**: `docs/ideas/idea-summary.md`

サマリーには対話で引き出した内容をすべて含め、後工程の要件定義がスムーズに始められる状態にしてください。

フェーズ1が完了したら、ユーザーに承認を求めてください。承認が得られたらフェーズ2へ進みます。

---

## フェーズ2: 要件定義書の作成

`Skill('requirements-definition')` を使って要件定義書を作成します。

- 保存先: `docs/specs/requirements-definition.md`
- 詳細な手順は `requirements-definition` スキルに従ってください

フェーズ2が完了したら、ユーザーに承認を求めてください。承認が得られたらフェーズ3へ進みます。

---

## フェーズ3: 基本設計書の作成

要件定義書の作成が終了したら、次は基本設計書の作成に入ります。

### 基本設計書の目的

要件定義書をもとに、システムをどのように構築するかの方針を定めます。開発者が実装に着手できるレベルまで設計を具体化することが目標です。

### 基本設計書の標準構成

1. システム概要
2. システムアーキテクチャ
3. 機能一覧・画面一覧
4. データモデル（ER図・テーブル定義の概要）
5. API設計の概要
6. 非機能設計（セキュリティ、パフォーマンス、可用性）

### 作成手順

1. `docs/specs/requirements-definition.md` を読み込む
2. 上記の標準構成に沿って基本設計書のドラフトを作成する
3. 以下の観点でレビューする
   - 要件定義書のすべての機能要件が設計に反映されているか
   - 技術スタック（Python/Django/React/PostgreSQL）に沿った設計になっているか
   - データモデルが機能要件を満たしているか
   - 非機能要件（可用性・性能・セキュリティ）が設計に反映されているか
4. 完成した基本設計書を `docs/specs/basic-design.md` に保存する

フェーズ3が完了したら、ユーザーに承認を求めてください。承認が得られたらフェーズ4へ進みます。

---

## フェーズ4: 詳細設計書の作成

基本設計書の作成が終了したら、次は詳細設計書の作成に入ります。

### 詳細設計書の目的

基本設計書をもとに、実装に必要な詳細な仕様を定めます。開発者がコードを書き始めるのに十分な粒度で設計を具体化することが目標です。

### 詳細設計書の標準構成

1. モジュール構成・ファイル構成
2. クラス・関数の設計（主要なもの）
3. テーブル定義（詳細）
4. APIエンドポイント定義（詳細）
5. 画面遷移・コンポーネント設計
6. エラーハンドリング方針
7. テスト方針の概要

### 作成手順

1. `docs/specs/requirements-definition.md` と `docs/specs/basic-design.md` を読み込む
2. 上記の標準構成に沿って詳細設計書のドラフトを作成する
3. 以下の観点でレビューする
   - 基本設計書のすべての設計要素が詳細化されているか
   - 開発者がこの設計書だけを見て実装に着手できるか
   - テーブル定義とAPIが整合しているか
   - エラーケースや例外処理が考慮されているか
4. 完成した詳細設計書を `docs/specs/detailed-design.md` に保存する

フェーズ3が完了したら、ユーザーに承認を求め、プロジェクト初期化の完了を伝えてください。

---

## 完了時のメッセージ例

すべてのフェーズが完了したら、以下の内容をユーザーに伝えてください。

- 作成されたドキュメント一覧（パス付き）
- 次のステップ（作業計画の作成や実装フェーズへの移行）

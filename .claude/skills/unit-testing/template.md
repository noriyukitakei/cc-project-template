# 単体テスト仕様書

各テストケースは「メタブロック（固定フィールド）＋詳細セクション」のブロック形式で記述する。

- メタフィールドは値を固定し、後段の自動抽出（実行手段ごとのグループ化・手動ケースの抽出など）を安定させる。
  - `実行手段` は `pytest` 等のツール名、または `manual` のいずれか（自由文禁止）。`manual` が旧 `自動化: manual` を兼ねる。
  - `実行手段: manual` の場合は `理由` を必須とする（なぜ自動化できないかを1行で）。
- `ID` は見出しとフィールドの両方に持たせ、テストコード・CIレポート・実行管理を貫通するキーとする。
- 合否などの実行結果はここに書かない（仕様書は仕様の正本であり、結果は CI / 実行管理側で持つ）。
- 単体テストは原則コードで自動化する（既定の実行手段は技術スタックに従う。例: `pytest`）。入力と期待結果が明確なため、手順は省略してよい（`parametrize` 等にそのまま対応する）。

## UT-LOGIN-001 ログイン成功

- **ID**: UT-LOGIN-001
- **観点**: 正常系
- **実行手段**: pytest
- **理由**: -

### 概要

正常な認証情報でログインできることを確認する。

### 前提条件

- ユーザーが登録済みであること
- DBへ正常に接続できること

### 入力

- email: test@example.com
- password: correct-password

### 期待結果

- HTTP Status が 200 であること
- token が返却されること
- エラーが発生しないこと

### 備考

MailService は Mock を利用する。

## UT-LOGIN-002 パスワード不一致

- **ID**: UT-LOGIN-002
- **観点**: 異常系
- **実行手段**: pytest
- **理由**: -

### 概要

不正なパスワードでログインした場合に、適切なエラーが返却されることを確認する。

### 前提条件

- ユーザーが登録済みであること
- DBへ正常に接続できること

### 入力

- email: test@example.com
- password: wrong-password

### 期待結果

- HTTP Status が 401 であること
- token が返却されないこと
- 認証エラーが返却されること

### 備考

エラーメッセージおよびエラーコードを確認対象に含める。
